🔵 Primeiros Passos no PowerShell

🔬 Laboratório ⏱ 30 min

📋 Enunciado

Abra o PowerShell e execute uma série de cmdlets básicos, observando e documentando os resultados de cada um.

📊 Rubrica de Avaliação
Critério Insuficiente (0–5) Básico (6–7) Proficiente (8–9) Excelente (10)

✅ Resolução Passo a Passo

  1. ▸ Abra o PowerShell como Administrador: Win+X → Windows PowerShell (Admin)
  2. ▸ Comando 1: Get-Host → mostra a versão do PowerShell
  3. ▸ Comando 2: $PSVersionTable → informações detalhadas da versão
  4. ▸ Comando 3: Get-Date → mostra a data e hora atual
  5. ▸ Comando 4: Get-Command → lista TODOS os cmdlets disponíveis (vai ser muito!)
  6. ▸ Comando 5: Get-Command *process* → filtra cmdlets que contêm 'process'
  7. ▸ Comando 6: Get-Help Get-Process → mostra a ajuda do cmdlet Get-Process
  8. ▸ Comando 7: Get-Help Get-Process -Examples → mostra exemplos de uso
  9. ▸ Para cada comando, tire um print e anote o que ele fez. Salve: 'sem08_ex1_SeuNome.docx'

💡 Dica Profissional: Sempre documente o que você fez durante o laboratório. Um técnico sem registros não consegue reproduzir soluções nem comprovar seu trabalho.

🔷 Navegação e Sistema via PowerShell

🔬 Laboratório ⏱ 35 min

📋 Enunciado

Use o PowerShell para navegar pelo sistema de arquivos e obter informações do sistema, comparando com os comandos equivalentes do Prompt de Comando.

📊 Rubrica de Avaliação
Critério Insuficiente (0–5) Básico (6–7) Proficiente (8–9) Excelente (10)
Funcionamento Não funciona Funciona parcialmente Funciona corretamente Funciona perfeitamente e supera
Estrutura Técnica Estrutura inadequada Estrutura básica funcional Boa estrutura técnica Estrutura exemplar e profissional
Tratamento de Erros Sem tratamento de erros Tratamento mínimo presente Erros bem tratados Tratamento robusto e completo
Eficiência Ineficiente e redundante Pouco eficiente Eficiente Altamente eficiente e otimizado
Documentação Sem comentários ou README Documentação básica Bem documentado Documentação completa e exemplar
Boas Práticas Sem boas práticas Algumas boas práticas Boas práticas aplicadas Segue padrões profissionais

✅ Resolução Passo a Passo

  1. ▸ Get-Location → mostra o diretório atual (equivalente a: cd no cmd)
  2. ▸ Set-Location C:\ → vai para a raiz do C: (equivalente a: cd C:\)
  3. ▸ Get-ChildItem → lista arquivos e pastas (equivalente a: dir)
  4. ▸ Get-ChildItem -Hidden → lista também arquivos ocultos
  5. ▸ Set-Location C:\Windows\System32 → navegue até System32
  6. ▸ Get-ChildItem *.exe | Measure-Object → conta quantos .exe existem nessa pasta
  7. ▸ Get-ComputerInfo | Select-Object OsName, TotalPhysicalMemory → info do PC
  8. ▸ Get-Process | Sort-Object CPU -Descending | Select-Object -First 10 → top 10 processos por CPU
  9. ▸ Crie tabela comparativa: PowerShell | CMD | O que faz. Salve: 'sem08_ex2_SeuNome.docx'

💡 Dica Profissional: Sempre documente o que você fez durante o laboratório. Um técnico sem registros não consegue reproduzir soluções nem comprovar seu trabalho.

🟢 Configurando o Perfil do PowerShell

🔬 Laboratório ⏱ 25 min

📋 Enunciado

Configure o ambiente PowerShell com um perfil personalizado que carrega aliases e funções úteis automaticamente.

📊 Rubrica de Avaliação
Critério Insuficiente (0–5) Básico (6–7) Proficiente (8–9) Excelente (10)
Diagnóstico Não identificou o problema Diagnóstico superficial Bom diagnóstico Diagnóstico preciso e completo
Raciocínio Técnico Sem raciocínio lógico Raciocínio básico Bom raciocínio técnico Raciocínio exemplar e sistemático
Solução Aplicada Solução incorreta ou ausente Solução parcial Solução adequada Solução ótima e elegante
Documentação do Processo Sem registro do processo Registro mínimo Processo bem documentado Documentação técnica completa
Eficácia Problema não resolvido Parcialmente resolvido Resolvido satisfatoriamente Resolvido com excelência
Comunicação Incapaz de explicar Explicação básica Explicação clara Comunicação técnica exemplar

✅ Resolução Passo a Passo

  1. ▸ Verifique a política de execução: Get-ExecutionPolicy
  2. ▸ Se necessário, altere: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
  3. ▸ Verifique se o arquivo de perfil existe: Test-Path $PROFILE
  4. ▸ Crie o arquivo de perfil: New-Item -Path $PROFILE -Type File -Force
  5. ▸ Abra o perfil para edição: notepad $PROFILE
  6. ▸ Adicione no perfil: Set-Alias -Name gs -Value Get-Service
  7. ▸ Adicione: Set-Alias -Name gp -Value Get-Process
  8. ▸ Adicione: Write-Host 'PowerShell carregado!' -ForegroundColor Green
  9. ▸ Feche e reabra o PowerShell — veja a mensagem aparecer
  10. ▸ Teste: gs → deve listar os serviços (alias funcionando!)
  11. ▸ Salve o conteúdo do perfil e documente. Salve: 'sem08_ex3_SeuNome.docx'

💡 Dica Profissional: Sempre documente o que você fez durante o laboratório. Um técnico sem registros não consegue reproduzir soluções nem comprovar seu trabalho.

☑️ Checklist de Entrega:

Verifique a política de execução: Get-ExecutionPolicy
Se necessário, altere: Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
Verifique se o arquivo de perfil existe: Test-Path $PROFILE
Crie o arquivo de perfil: New-Item -Path $PROFILE -Type File -Force
Arquivo salvo com nomenclatura correta (sem08_ex3_SeuNome)
