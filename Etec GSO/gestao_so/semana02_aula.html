📖 1. Arquitetura do SO: Kernel e User Mode

🏗️ A ideia de "camadas"

O SO é organizado em camadas, como as camadas de uma cebola. As camadas mais internas têm mais poder (e mais responsabilidade). As mais externas são onde você interage. Isso é importante para segurança: um programa que trava não pode travar o sistema todo, porque está em uma camada mais externa.

🏗️ Arquitetura em Camadas do Windows
👤 Usuário — Você, usando o computador
⬇️
📱 Aplicativos — Word, Chrome, Spotify, Jogos
⬇️
🪟 User Mode (SO) — Interface, APIs, Serviços
⬇️
⚙️ Kernel Mode — Núcleo do SO (acesso total ao hardware)
⬇️
🔧 Hardware — CPU, RAM, Disco, Placa Mãe

⚙️ Kernel Mode — O "núcleo duro" do SO

O Kernel tem acesso total ao hardware. Ele controla diretamente o processador, a memória e os dispositivos. É o componente mais crítico — se o Kernel travar, o sistema inteiro trava (a famosa "tela azul da morte" ou BSOD no Windows). Por isso, apenas componentes do próprio SO rodam no modo Kernel.

💡 A "Tela Azul da Morte" (BSOD) acontece quando um problema ocorre no Kernel Mode. Como técnico, você vai aprender a diagnosticá-la!

👤 User Mode — Onde seus programas rodam

Todo programa que você instala (Word, Chrome, jogos) roda no User Mode, com acesso restrito. Isso é segurança: se o Chrome travar, o Windows continua funcionando porque o Chrome não tem acesso direto ao hardware. Ele precisa "pedir" ao Kernel para fazer coisas mais críticas.

⚠️ Curiosidade: vírus e malwares tentam "sair" do User Mode e entrar no Kernel Mode para ter mais poder. Por isso o Windows tem proteções como o UAC (Controle de Conta de Usuário).

📖 2. Gerenciamento de Processos e Memória

⚙️ O que é um processo?

Um processo é um programa em execução. Quando você abre o Word, o SO cria um processo chamado "WINWORD.EXE". Esse processo tem um PID (Process ID — número único), usa uma quantidade de RAM, CPU e pode ter prioridade diferente. O SO decide qual processo usa o processador a cada milissegundo.

💡 Abra o Gerenciador de Tarefas agora: Ctrl + Shift + Esc → aba "Detalhes" para ver todos os PIDs dos processos!

📊 Estados de um processo

Um processo pode estar em 3 estados: Executando (usando o processador agora), Pronto (esperando sua vez para usar o processador) ou Bloqueado/Aguardando (esperando algo externo, como uma resposta de internet ou leitura de disco). O escalonador decide quem roda quando.

💾 Gerenciamento de Memória RAM

O SO distribui a RAM entre todos os processos ativos. Cada processo tem sua área de memória isolada (um processo não pode ler a memória de outro — segurança!). Quando a RAM está cheia, o Windows cria o arquivo de paginação no disco (memória virtual) para compensar — mas é muito mais lento.

⚠️ Por isso o computador fica lento quando a RAM enche! O disco é ~100x mais lento que a RAM. A solução: mais RAM ou fechar programas que não está usando.

🪟 Edições do Windows no Mercado

Windows 11 Home: para uso doméstico, notebooks pessoais. Windows 11 Pro: adiciona BitLocker (criptografia), domínio de rede, Hyper-V — ideal para empresas. Windows 11 Enterprise: para grandes corporações, com gerenciamento centralizado. Windows Server 2022: para servidores e data centers. No mercado, ainda há muitas máquinas com Win 10 aguardando migração!

Quiz 2 – Processos, Memória e Edições

⚡ +50 XP
1
O que é o PID de um processo?
✅ Correto! PID = Process ID. É o "RG" do processo — número único para identificá-lo no sistema.
❌ Errou! PID (Process ID) é um número único para cada processo, como um RG. Veja no Gerenciador de Tarefas!
2
Por que o computador fica lento quando a RAM está cheia?
✅ Perfeito! O disco é ~100x mais lento que a RAM. Memória virtual = lentidão!
❌ Não! Quando a RAM enche, o Windows usa o disco como memória virtual (arquivo de paginação) — e disco é muito mais lento!
3
Qual edição do Windows tem recursos como BitLocker e Hyper-V, sendo ideal para empresas?
✅ Windows 11 Pro! BitLocker para criptografia, Hyper-V para virtualização, entrada em domínio.
❌ Errou! Windows 11 Pro é a edição voltada para empresas com BitLocker, domínio e Hyper-V.
4
Um processo "Bloqueado" está em qual estado?
✅ Correto! Bloqueado = aguardando evento externo (dados do disco, rede, input do usuário).
❌ Não! Bloqueado significa que o processo está esperando algo externo (como resposta de uma chamada de rede) antes de continuar.
